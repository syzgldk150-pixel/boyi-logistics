# 博益原页助手 0.4.11

作用于 https://boyi.homes/ocr 中的韵达、融辉、百世真实原页，由博益后台提供安装包。从主站任意页面加载监听器，支持局部导航。源码目录与下载地址沿用现有融辉扩展；更新现有安装即可。融辉和百世先完成登录适配再请求原站，手动重载也重新准备，失败不自动重试。

## 使用

更新或在扩展管理页重新加载助手后，旧博益网页中的扩展连接会失效。请先保存所有页签中未保存的内容，再刷新**整个博益网页**；原页工具栏的“重新加载”只重载内嵌页，不能恢复主网页的扩展连接。0.4.5 会识别这类失效并提示整页刷新，不自动刷新或丢弃其他页签的草稿。准备失败本身不代表扩展版本过旧；其他准备错误仍明确报错，不自动重试。

韵达未登录时，内嵌区域显示“打开韵达扫码登录”，点击后在独立窗口扫码；也可使用页签顶部的新窗口链接。不要在旧版内嵌二维码中扫码。成功后关闭本次登录辅助页，回到发起登录的博益页面并重新加载对应原页，不刷新其他正在填写的页签。韵达登录后的首页自动进入真实录单地址；融辉优先切换到已有“运单录入”，没有时调用原站菜单打开一次，再收起原站导航。首次打开可能按原站设置领取单号，不提交保存、上传或打印。
上方“原站菜单”按钮可恢复完整原站，便于切换账号及使用其他功能；点击“仅显示录单”返回已打开的录单页。
菜单往返只调整布局，不重新加载、搬移或替换表单 iframe。同一个融辉系统页面只自动进入一次，关闭录单页不会立即重开。单独打开的原站标签不自动跳转。
登录页和单独在浏览器打开的融辉原站不改变布局。无账号隔离，同一浏览器的融辉标签共享账号。

## 百世录入

0.4.10 在博益内嵌的新版录单页默认收起顶部蓝色导航栏，保留“首页／首页(旧)／运单录入”页签、草稿箱、上传与打印工具栏、完整表单和地图。上方“原站菜单”可以恢复导航，“仅显示录单”再次收起；只调整现有页面布局，不重载或替换表单。上传、保存等工具栏随表单滚动，展开菜单时也不固定在屏幕上。独立原站窗口保持原样。

0.4.9 将录单入口改为用户确认的 `https://v5.800best.com/baseService/transOrder/networkProductOrder`（原站含“仓线计划”的新版表单）。博益页签、独立登录辅助页、登录完成路径核验及内嵌适配统一使用此路径，旧 `createOrder` 不再自动处理。真实 Chrome 与完整 0.4.9 扩展已验证新版内嵌、小“运单录入”自动选中及已登录辅助窗口返回；本轮没有重新扫码，扫码过程仅由隔离回归模拟覆盖。下述 0.4.8 及更早实测对应旧录单入口。

0.4.8 修复登录后不能进入内嵌录单：百世前端用 JavaScript 写入的登录标记可能没有 Secure 属性，仅有 HTTPS 主机权限时扩展读不到这些标记。新增精确的 `http://v5.800best.com/*` 权限仅用于本机 Cookie 适配，原页仍使用 HTTPS；已打开百世内嵌页时监听其 Cookie 更新，补齐 SameSite/Secure，忽略删除和已适配事件，避免原站刷新标记后再次失效。

百世还将原生用户资料与网点目录存于 localStorage / IndexedDB，Chrome 的跨站存储分区使内嵌页无法直接使用独立窗口的这些数据。`best-storage.js` 仅在博益直接内嵌的百世录单入口、原站脚本启动前，通过浏览器 Storage Access API 取得同源存储句柄并提供给原站；扩展不读取、复制或传送其中的数据，不修改独立页、登录页或其他来源的内嵌页。只给百世 frame 增加 `allow-storage-access-by-user-activation`，不放开顶层跳转。浏览器拒绝时明确提示网站数据权限或在新窗口录单。

辅助窗口完成后，主站激活发起登录的内部页签，再重载该页；百世原页首次自动选择自己的小“运单录入”标签。SPA 的 URL 单独改变也会触发登录核验，避免 DOM 先更新导致错过返回。其他草稿及用户随后手动选择草稿箱的行为不变。

0.4.6 修复扫码窗口提前关闭：百世可能先显示缓存中的“运单录入”标签，再由接口返回登录失效。助手只在真实菜单接口 `/ltlv5-war/web/menu/getUserMenuVos` 返回成功状态 `200` 且菜单结构有效后通知博益返回；`40001`、网络失败或无效响应都保留原站窗口。验证沿用当前浏览器会话，10 秒超时，不读取或传送登录信息。登录页与录入页的同文档路由切换持续观察；离开录入页后到达的旧验证结果不得关闭窗口，同一路由不因 DOM 变化重复验证。

0.4.4 增加百世原站访问权限。博益“百世原页”创建内部页签，先在浏览器本机适配现有会话的 SameSite/Secure 属性，再加载 `/baseService/transOrder/createOrder`。该地址默认打开草稿箱；`best-entry.js` 根据真实原页的 `[role=tab]` 精确找到唯一“运单录入”并点击一次，通过可见面板的 `#code` 与 `#sendPhone` 确认表单。30 秒未完成时提示手动切换或重载，不任取候选、不循环点击。独立原站标签和其他站点内嵌不自动切换。

未登录时在博益显示“打开百世扫码登录”，辅助窗口完成登录后只返回并重载发起页签。不会操作上传服务器、保存、打印、表单内容或切换账号；人工切回草稿箱不被再次抢回。登录状态仅在本机浏览器使用，不复用 Agent 账号会话。百世登记的页签 ID 存于扩展会话存储，关闭页签时清理；恢复扩展后台进程时保留本次浏览器会话登记。

## 地址匹配与开单打印

0.4.11 修复在博益内嵌的融辉登录页里登录后，录单页网点、地图和地址匹配全部失效。真实登录页登录成功后执行 `mini.Cookie.set("userInfo", ...)`，MiniUI 以 `document.cookie` 写入且不带 SameSite/Secure；Chrome 按 Lax 处理并在跨站 frame 中直接丢弃这次写入，不产生 Cookie 变更事件，0.4.9 的后台适配无从修复，`crud.init` 随后读不到 `loginSiteName`。`cookie-writes.js` 只在顶层为博益的融辉 frame 中，于原站脚本运行前为其自身的 `document.cookie` 写入改用 `SameSite=None; Secure`，名称、取值、路径、有效期和域保持原样；不读取、复制或补造资料，不重放初始化。单独打开的原站标签不注入，仍由 0.4.9 的后台适配处理顶层写入。

0.4.9 补齐融辉原站 JavaScript 更新登录资料 Cookie 后的持续适配。故障页已确认可访问第三方存储，但原站将 host-only `userInfo` 写为非 Secure、SameSite=Lax；跨站录单读不到资料时，`crud.setSendData` 读取 `loginSiteName` 报错，导致 `crud.init` 中断，网点、地图和地址处理一起未完成。已登记融辉内嵌标签期间，助手沿用现有本机适配器补齐后续更新的 SameSite/Secure；删除、已适配事件和无关域不处理，不扩展主机权限、不补造资料、不重放原站初始化。用户更新助手并刷新博益整页后，已在原故障 Chrome 中确认寄件网点、地址解析和地图全部恢复。

0.4.3 修复收件详细地址的回车/失焦事件：真实 MiniUI 事件未携带 `value`，原页却用 `test(e.value)` 查询 `/map/inputtipsDTH`。扩展只在博益内嵌录单页给这两个事件补齐当前字段值，随后执行原生处理。原站已有的事件值（包括清空地址）原样保留，不自动选择候选、不调用替代接口、不记录地址或账号信息。

保存仍使用原站校验、费用计算和提交；成功后由原站按“是否打印主单/子单/回单”选项读取刚保存的运单并调用本机 C-Lodop。补打继续从“原站菜单”的运单管理进入。扩展不隐藏或替换这些业务流程，也不把原站隐藏的调试打印按钮开放给用户。地址补齐不改变保存和打印函数，不改变 iframe 的表单、弹窗、下载权限。

## 登录适配

0.4.2 在真实韵达登录页确认了顶层跳转逻辑；该行为被博益 iframe 沙箱阻止。扩展仅在韵达 `/login` 且直接嵌于博益时发送不含登录信息的通知，主站核对来源及对应 frame 后隐藏内嵌登录，显示独立窗口入口。登录成功或手动重载时恢复同一个录单 frame。独立登录页保留原站扫码流程，不读取或转发扫码结果，不开放顶层跳转权限。

韵达在 `/login` 将 `#third_qrcode_container` 固定为 294px 高，并在 `/public/feishu/login` 设置标题行高 24px、下间距 12px。嵌入沙箱时原站自动调整高度未生效，窗口停在 250px；只修改标题仍会裁掉底部。两层 CSS 保留原二维码尺寸和扫描链接，不读取二维码内容。

新增 `storage` 权限只在浏览器会话内保存辅助页、来源页签和平台的对应关系，辅助页关闭即删除，不保存账号、凭据或业务字段。就绪消息必须匹配平台来源、允许路径、顶层页面及已登记的辅助页；只自动返回本次明确打开的登录窗口。

扩展在浏览器本机适配融辉和百世 Cookie 的 SameSite/Secure 属性，并将已观察到的 HTTP 登录跳转改为 HTTPS。
登录信息只在浏览器内存中处理，不输出、不存文件、不上传。不改写业务请求正文或 CSP/X-Frame-Options。
停用/移除扩展后适配停止；已适配的 Cookie 属性保留到原站重设 Cookie 或用户正常退出、清理该站数据。

## 安装

从博益融辉页签的“下载内嵌扩展”取得 ZIP，解压到固定文件夹。打开 chrome://extensions（Edge 为 edge://extensions），开启开发者模式，选择“加载已解压的扩展程序”，选择包含 manifest.json 的 extension 文件夹。Edge 兼容性仍待实测。
更新已有扩展时覆盖本目录，在扩展管理页点重新加载，然后先保存现有录单内容，再刷新整个博益网页或打开新的博益网页。
有未保存录单时不要刷新业务页面；请完成当前录单后再打开新页面。ECS 发布不会自动安装或升级每台电脑上的浏览器扩展。
