# 已验证空快照与自动化阻塞状态设计

## 背景

`arrive_list` 在权威来源完整返回零条记录后，仍依次清空 MySQL 快照并调用飞书表格覆盖。飞书空数据覆盖未形成闭合读回证据，Run 因而进入 `BLOCKED_DATA/WRITE_OUTCOME_UNKNOWN`。Console 又把所有非运行、非审批但尚未生成终态 runtime 的 Run 统一显示为“等待状态同步”，造成任务一直运行的错觉。

本设计把“零条权威数据”定义为需要提交并验证的空快照，而不是跳过同步，也不是未验证地清空目标。

## 目标行为

当来源查询满足以下全部条件时，进入空快照路径：

- 请求成功且身份、账号和目标日期闭合；
- 所有分页均已读取，`pagination_complete=true`；
- 没有解析错误、缺失页、重复游标或登录异常；
- 业务过滤后的当前目标集合为零条。

空快照路径必须：

1. 清空目标日期对应的 MySQL 投影或当前快照。
2. 清空飞书数据区域，保留列头、格式、边框和工作表结构。
3. 更新日期标题为目标业务日，例如 `08.24运单编号`。
4. 从每个目标重新读取数据区域、标题和 MySQL 投影。
5. 只有所有必需目标都证明数据条数为零且标题日期正确时，才返回 `SUCCESS/COMPLETED`。
6. 结果投影显示“无数据，已清空并更新日期”，并记录 `execution_result=no_data_cleared`、目标日期和零条记录证据。

来源请求失败、分页不完整、登录失效或无法区分“无数据”与“未读取到数据”时，不得进入空快照路径。

## 覆盖范围

### `arrive_list`

- 清空 `waybill_data` 当前快照并精确读回零条。
- 清空主、次两张到货表的数据区域。
- 主、次表标题日期均更新为目标业务日。
- 清空并验证到货预测快照。

### `arrival_stats`

- 当目标日到货清单与扫描集合均为空时提交空统计快照。
- 清空统计主表、次表、待到货表和分批待处理表的数据区域。
- 保留各表既有表头结构，并按其现有布局更新目标日期。
- 空数据不得创建无意义的历史归档行。

### 其他快照型自动化

- `site_send`：保留现有“空源、空目标为已验证 no-op；空源、非空目标执行清空”的语义，并统一成功结果文案。
- `scan_codes`：空源时清空并读回扫描快照，不产生扫描提交批次。
- `daily_send_orders`：清除目标日期的飞书与 SQL 数据，读回目标日期集合为空。
- `sync_yunda_send_waybills`：清除目标日期的多维表和 SQL 数据；普通表格仅在当前配置要求同步时清空并验证。
- `delivery_status`、财务同步、客服问题件和已具备闭合 `no_data` 语义的任务保持现有行为，不增加无意义写入。

每个自动化必须复用其既有签名资源绑定、字段 Schema、目标日期和写后读取适配器，不新增通用裸写入口。

## 写入顺序与证据

- 每个 Broker mutation 在首次可能改变外部状态前记录持久化写尝试回执。
- 每个目标写入后立即执行独立 fresh readback；通用成功响应、HTTP 200 或写接口返回值不能代替读回。
- 空快照证据至少绑定自动化 ID、generation、Run、step、目标资源、目标日期、零条记录、标题值和内容哈希。
- 所有目标验证完成后，回执更新为 `WRITE_VERIFIED`，Run 才能完成。
- 某一目标失败时，已开始的写不得盲目重放；使用同一请求的精确 readback 协调已完成、未发生或未知结果。
- 无法证明结果时保留 `WRITE_OUTCOME_UNKNOWN` 审计，不伪造成功。

## Console 状态语义

- `BLOCKED_DATA` 显示“数据阻塞”，并展示服务端脱敏后的具体原因。
- `BLOCKED_LOGIN` 显示“登录已失效”。
- 这两种状态不再显示“等待控制平面进入下一状态”，也不再按运行中状态每秒轮询。
- `WAITING_APPROVAL`、真正的 `RUNNING/VERIFYING` 和命令刚受理但尚未领取的状态继续使用各自现有显示。
- 空快照成功时显示“无数据，已清空并更新日期”，按钮恢复为可再次执行状态。

## 测试设计

- 每个修改的签名 action 先增加空来源失败测试，证明当前实现仍会调用不应调用的写路径或无法完成。
- 覆盖“目标原本非空”和“目标原本已空”两种情况。
- 验证数据区域为零、日期标题正确、格式区域未被修改、MySQL 读回为零。
- 验证分页不完整、登录失败和解析失败不会被误判为无数据。
- 验证部分写入、响应丢失和 fresh readback 不一致仍进入未知写保护且不自动重放。
- Console 覆盖 `BLOCKED_DATA`、`BLOCKED_LOGIN`、`COMPLETED/no_data_cleared` 的标签、轮询和按钮状态。
- 运行签名包、Broker、生产适配器、Console JavaScript、runtime generation、未知写恢复和发布边界测试。

## 发布与生产验收

- 修改签名 payload 时提升第一方插件版本，重新构建并使用受保护的本机发布密钥签名。
- 通过 Draft PR、CI 和最终审查后合并 `main`，创建与 `main` SHA 一致的生产标签并使用固定发布器紧急发布。
- 生产验收先使用空来源或已知空目标日期执行，确认 Run 进入 `COMPLETED`，飞书数据区为空、标题为目标日、MySQL 投影为空。
- ECS、GitHub `main`、本地 `main` 和生产标签必须保持同一 SHA。
- 历史未知写与取消记录继续保留审计，不修改为成功。

## 非目标

- 不取消签名、账号、入口、参数或写后证据校验。
- 不把真实读取失败当作空数据。
- 不删除表头、格式、工作表或资源绑定。
- 不通过重试掩盖未知写，也不修改历史 Run 结论。
