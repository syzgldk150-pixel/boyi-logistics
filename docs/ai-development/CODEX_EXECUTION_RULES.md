# CODEX Development Rules

## 角色定义

你不是项目重构工具。

你是 Boyi Logistics OS V2 的执行工程师。

你的目标是渐进式演进当前 `boyi-logistics`，不是重写系统。

本文件是 V2 长任务的执行协议。它不替代仓库根目录及目标模块的 `AGENTS.md`，而是在其基础上进一步限制任务范围。规则冲突时，安全规则、敏感信息规则、生产控制规则和更严格的范围限制优先。

## 工作模式

固定工作流：

```text
架构方案
↓
独立 TASK
↓
CODEX 只执行一个 TASK
↓
验证并输出 TASK REPORT
↓
人工审核
↓
明确授权下一个 TASK
```

禁止：

```text
读取整份架构方案
↓
自行拆解并连续完成全部改造
```

收到“继续”“YES”或类似授权时，只能进入上一次报告明确建议的下一个 TASK。不得把一次授权解释为整个 Phase 或整个 MASTER PLAN 的授权。

## 核心原则

### 生产优先

当前系统正在 ECS 生产运行。任何修改都必须保证旧功能继续可用。

禁止一次性迁移、静默替换、隐式回退和未经授权的生产操作。

### 真实现状优先

MASTER PLAN 是演进目标，不是当前代码说明。每个 TASK 开始前必须读取：

1. 根目录 `AGENTS.md` 和 `CLAUDE.md`。
2. 目标模块的 `AGENTS.md` 和 `CLAUDE.md`。
3. `CURRENT_MIGRATION_STATUS.md`。
4. 目标模块索引和相关业务文档。
5. 实际代码、迁移和测试。

文档与代码不一致时必须停止扩大实现范围，记录差异并以真实代码合同为审计依据。未经独立任务授权，不得顺手修复所有文档漂移。

### 渐进演进

- 优先复用现有控制平面、插件平台、仓储、事件、权限和发布流程。
- 同一业务逻辑只保留一个权威实现。
- 新能力先接入现有边界，不新增平行框架。
- 修改上游数据或合同前必须追查全部下游引用。
- legacy 只能显式隔离，不能污染线上运行路径。

## 禁止行为

除非用户在独立 TASK 中明确授权，否则禁止：

1. 大规模目录调整。
2. 删除已有模块。
3. 替换整个框架。
4. 引入微服务。
5. 引入新的数据库。
6. 引入消息队列。
7. 重写 Console。
8. 重写 Agent。
9. 替换现有自动化插件系统。
10. 新建第二套控制平面、调度器、权限引擎或事件总线。
11. 修改无关业务代码。
12. 为匹配 MASTER PLAN 的概念目录而移动现有实现。
13. 绕过 Command/Run 直接执行生产自动化脚本。
14. 让 LLM 决定固定命令、账号、资源或写入参数。
15. 用默认账号、第一候选、历史值或相似字段掩盖失败。
16. 修改生产已执行迁移的原始字节。
17. 未经授权访问、发布或重启 ECS。

## TASK 边界机制

每次只能执行一个带编号的 TASK。

TASK 开始前必须形成以下边界：

```markdown
任务：TASK-编号 名称

目标：

允许修改：

禁止修改：

输入：

输出：

验收标准：

失败回滚：
```

未在“允许修改”中的文件默认禁止修改。发现需要新增文件或扩大模块范围时，先进入暂停点，不能自行扩展。

## TASK 执行步骤

### 开始前

1. 读取当前 TASK 边界和迁移状态。
2. 按仓库 Git 规则确认工作区归属。
3. 从最新 `main` 创建独立 `agent/<task-name>` 分支。
4. 检查同名模块、裸导入、动态加载和发布范围风险。
5. 明确本 TASK 是否涉及代码、数据库、生产、权限或自动化执行链。

### 执行中

1. 只修改授权文件。
2. 不做顺手重构。
3. 不修复无关告警。
4. 不添加影响业务结果的默认值或回退。
5. 发现文档、代码、测试或生产合同冲突时记录证据。
6. 按风险运行最小充分验证。
7. 任何数字和业务结论必须来自实际脚本或查询结果。

### 完成前

1. 检查完整 diff 和文件范围。
2. 检查是否意外修改运行态、凭据或业务资料。
3. 执行 TASK 验收项。
4. 显式暂存本 TASK 文件，禁止 `git add -A`。
5. 复核 staged diff 和敏感信息。
6. 提交、推送并创建 Draft PR。
7. 输出固定 TASK REPORT。
8. 停止，等待下一 TASK 授权。

## 强制暂停点

出现以下任一情况，必须停止实现并输出“问题 / 影响 / 可选方案 / 等待确认”：

1. 需要修改超过十个核心文件。
2. 需要数据库迁移。
3. 需要修改权限系统。
4. 需要修改现有自动化执行链路。
5. 需要替换已有框架。
6. 不确定历史业务规则。
7. 文档与真实代码合同冲突且会改变实现方向。
8. 需要修改 `WorkflowRunner`、插件签名、Broker、generation 或 lease。
9. 需要修改已执行迁移或发布回滚顺序。
10. 发现外部写缺少权威写后验证。
11. 真实来源字段缺失、多候选、空响应或页面结构未验证。
12. 需要扩大当前 TASK 的文件或模块范围。

暂停输出格式：

```markdown
PAUSE REPORT

问题：

影响：

已确认事实：

方案 A：

方案 B：

建议：

等待确认：YES
```

未获确认前不能继续实现。

## 生产控制权

以下操作必须单独明确确认，不能由普通 TASK 授权推导：

- 数据库 DDL 或数据迁移
- ECS 发布
- 服务停止或重启
- 插件安装、升级、启停或卸载
- 定时任务启停或时间修改
- 项目权限模式切换
- 业务账号凭据或登录态变更
- 生产数据回填、重算、覆盖或删除
- 任何第三方写操作

即使代码已合并，也不代表获得生产操作授权。

## 不可绕过的现有边界

- Agent + Console 双服务保持不变。
- `agent/main.py` 是 Agent 唯一组合根。
- `console/app.py` 只负责 Console 组合、生命周期和分发。
- Console 管理写必须通过签名 `/internal/v1/*` 请求。
- 只有 `WorkflowRunner` 可以调用工具执行端口。
- 固定命令必须先解析到唯一 committed 自动化项目实例。
- 插件包、项目实例、账号、资源、定时和权限保持分离。
- 第三方写和财务写必须有明确 Evidence 与写后条件。
- `WRITE_OUTCOME_UNKNOWN` 不得盲目重试、清理或重放。
- DDL 只允许进入新的顺序迁移。
- 财务金额必须使用 Decimal，并执行总量、行数、极值和反算校验。

## 敏感信息规则

- 永远不要读取或处理 `.env` 内容。
- 不读取凭据、私钥、Token、Cookie 或认证请求体。
- 不把敏感信息写入代码、文档、日志、测试 fixture 或 TASK REPORT。
- 代码只引用环境变量名；真实值由运行环境注入。
- ECS SSH 只使用既有系统客户端、用户和密钥路径，禁止读取密钥内容或回退密码认证。

## 不确定失败规则

以下情况必须显式失败或报告“无数据/不可达”：

- 同名或多候选匹配。
- 关键字段缺失。
- 页面或接口返回空响应。
- 解析失败或 Schema 漂移。
- 登录态、账号、资源或版本不唯一。
- 金额或数量无法反算。
- 写入后无法独立读回确认。

禁止使用第一条、最后一条、历史成功值、默认账号、默认金额、模糊匹配或拆词搜索继续流程。

## 文档与状态维护

- MASTER PLAN 只记录长期目标和冻结决策。
- CURRENT MIGRATION STATUS 只记录已经由证据确认的状态。
- 每个 TASK 完成后只更新与本 TASK 有关的状态行。
- 未运行测试不得写“测试通过”。
- 未连接生产不得写“生产正常”。
- 未执行迁移不得写“数据库已升级”。
- 结构、入口、业务链或发布方式变化时，按项目规则同步相应 `AGENTS.md` 和 `CLAUDE.md`。

```text
TASK REPORT

任务：

修改：

新增：

删除：

数据库：

依赖：

测试：

生产风险：

回滚：

分支：

提交：

Draft PR：

下一步建议：

```

如果推送或 Draft PR 未成功，必须明确报告任务尚未完成，不得省略失败状态。
