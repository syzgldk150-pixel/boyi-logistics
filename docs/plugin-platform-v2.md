# 独立插件与宿主接口

## 当前实现与线上状态

Service V2 插件是包含实际业务代码的独立 ZIP。宿主负责账号、权限、接口、隔离进程、执行记录和安装升级；插件负责字段适配、筛选、计算和业务步骤。短插件触发后直接启动，结束后返回结果，失败和取消不会留下待领取任务。

本轮源码已补齐现有正式业务的 V2 包和生产接口适配。安装、打包、隔离进程执行及写后核验均有实际测试。**源码和隔离测试完成不等于线上迁移完成。** 线上版本、迁移和业务验收须以发布报告为准；在现有实例完成切换前，启动和发布仍依赖旧 ACTION_V1 签名发行包，不得提前删除。

插件清单、业务文件归属、局部测试和打包命令见[当前插件维护入口](../agent/service_v2_plugins/README.md)。本手册替代旧文档中“生产 Connector 为空”“AI 只读”“V2 只有离线候选实现”的状态说明。

## 用户入口与权限

- `/automations` 管理功能插件的安装、设置、运行、定时、启停、升级和卸载。财务、客服采集放在各自模块的数据源入口，复用同一插件运行机制。
- 普通账号和飞书身份继承后台设置的身份权限，超级管理员拥有全部权限。权限变更实时影响页面、接口、固定查询及插件调用，见[身份与统一对话](identity_and_unified_chat.md)。
- Console AI 与飞书自然对话共用会话服务、当前激活模型和工具目录。固定关键词直接进入插件，不额外经过模型。账号与渠道身份仍分别核验。
- AI 可以调用当前身份获准使用的已安装插件。扫描、自提、分批先返回预览，正式执行使用宿主持有的一次性确认；模型不能自填账号、资源、执行身份或任意业务参数。
- 安装、升级和权限管理要求真实超级管理员。读取结果和执行插件使用当前角色权限及该插件的入口设置。

## 包合同与开发入口

ZIP 根目录包含 `manifest.json` 和 `payload/`；声明专属设置页时可包含 `settings/`。根目录不能再套一层文件夹。

Manifest 必须明确 `schema_version=2`、`runtime_model=service_v2`、版本、Host API 范围、运行方式、服务、操作、账号/资源角色、能力及贡献入口。解析 V2 失败直接拒绝，不尝试 V1。

V2 由超级管理员上传无签名 ZIP，按内容摘要确认传输及已安装字节；不使用 V1 的 Ed25519 包格式。相同版本不能覆盖不同内容。升级前检查权限、接口和配置兼容性；当前代切换完成后新调用才使用新包，旧调用排空。回退使用该实例已安装过的精确版本，不从同名目录猜测旧包。

Manifest Schema 位于 `agent/extension_sdk/schemas/manifest-v2.schema.json`。通用本地开发命令见 [Service V2 开发工具](../agent/docs/service_v2_developer_tooling.md)；现有业务优先使用 `agent/scripts/plugin_maintenance.py` 选择对应插件进行测试和打包。

设置页运行于独立 sandbox iframe，没有主页面同源权限或任意网络权限；通过会话绑定桥读取和保存自身配置。账号和表格只使用宿主返回的不透明引用。设置保存与定时保存分别校验版本并相互保留。

## 运行与宿主接口

插件采用 `on_demand` 独立进程，在 Linux Python 3.10、Bubblewrap 和资源限制下执行。`resident` 尚未实现，应明确返回 `RESIDENT_RUNTIME_UNAVAILABLE`。隔离环境不可用即失败，不在宿主进程回退执行。

每个服务操作声明精确 effect：`read`、`compute`、`internal_write`、`external_write` 或 `destructive`。预览按预览操作确定权限和读写类型，不因为同一包还有正式写操作而被视为写调用。

`service.invoke` 只接受 Manifest 声明的服务和操作。插件不能任意访问宿主 Python、SQL 连接、文件、网络或第三方凭据。宿主 `production_connectors.py` 注册已实现的到货、扫描、问题件、寄件、签收、财务、客服和每日应签接口。打卡复用已审核的 `browser.session` 动作。测试用 tracking fixture 只供显式隔离测试使用，不是生产物流接口。

Connector 在宿主解析当前账号和资源，验证输入和调用范围，并记录真实操作观测。敏感内部身份不进入模型或插件返回值。缺字段、分页不完整、范围不明、重复游标、空响应或权威回读失败必须给出具体失败结果；退出码或 `success=true` 不能替代业务成功。

写动作由宿主记录写尝试，完成后按具体业务进行独立回读和结果验证。写入结果未知时保留事实，不自动重发原写。新调用不查询历史失败记录决定准入；只有仍活跃的同实例调用及真实写目标协调会影响本次执行。

Registry 按已提交代次发布服务和入口。准备新代时完整校验，原子切换后才开放；停用、卸载和空代撤销实际路由。旧代可排空已开始的调用，但不继续接收新调用。

## 定时、飞书、Webhook 与事件

定时复用现有 APScheduler 和已保存时间，不生成默认业务时间、不补跑停机期间的任务。启用的定时贡献必须有真实 schedule。默认 cron 只接受当前宿主可无损表达的格式。

固定飞书命令及动态插件命令都使用可信消息身份和精确匹配，沿用登录、确认、取消等交互优先级。命令冲突拒绝整个新代，不选择第一个插件。单号文本使用统一确定性查询；自然语言对话才进入共用模型。

现有扫描、统计、签收状态三个 Webhook 的映射由 `shared/plugin_webhook_routes.py` 单点定义。迁移后仍在现有已验证入口上调用对应 V2，不开放任意新公网路由或任意请求参数。

通用 Webhook/Event Dispatcher 的 `READY` 只说明持久注册与当前进程入口绑定有效，不代表已经存在公网传输或外部事件总线。`durable=true` 事件仍不可用，不隐式降级。跨进程调度、持久事件重放及未来长任务不属于本轮短插件运行机制。

## 现有 V1 实例迁移

迁移使用代码审阅的一对一映射，复制当前实例的业务参数、账号、资源、定时和入口设置。不按名称猜测，不覆盖为包默认值，不把 route 当作业务表格。业务来源归属随切换迁移，人工录入内容保留。

| 状态 | 普通入口归属 | 目标验证 |
| --- | --- | --- |
| TESTING / READY | 原 V1 实例 | 超级管理员可从 Console 显式调用目标；定时、飞书、Webhook 和 AI 不提前接管 |
| CUTOVER / COMPLETED | V2 实例 | 使用原实例的启停状态和已保存入口 |
| ROLLED_BACK | 原 V1 实例 | 目标停用，原设置恢复 |
| PREPARING / 切换中 / 错误 | 未完成的目标不开放 | 明确报错，不能猜测归属 |

READY 要求目标当前代的新鲜成功 Direct Invocation 和该业务的实际验证结果。调用刚接受但尚未创建代次 lease 时也属于活跃执行，切换必须等其结束。失败、已取消和历史记录不形成积压锁。

TESTING 验证失败时可撤回迁移，保留原实例启停和入口、停用目标，并保留失败记录。撤回仍核验配置快照、活跃调用及未知写；管理员卸载撤回的目标、安装修复包为新目标后可显式开始新的迁移，ROLLED_BACK 历史不阻止重试，已 COMPLETED 的源实例仍不能重复迁移。原迁移的源/目标组合保持唯一，不能重写它的验证快照。

准备阶段尚未生成可运行版本时，也能撤回 TESTING；撤回不要求伪造成功结果。入口移交先撤销原持有者的进程路由，再同步新持有者，避免旧目标继续占用飞书命令。准备失败留下的未应用注册记录只允许按原代次清理，不能用于激活。

完成切换的源实例不再属于启动自动安装或旧版健康检查的必需集合，卸载后重启不会重新创建。原 018 发布回执永久保留；`agent/scripts/automation_project_release_migrations.py` 根据当前迁移事件、入口快照及源实例停用状态确定后续发布的检查范围，原首次发布的数量和策略校验不变。

切换前后保持原实例启停意图；原来停用的插件迁移后仍停用。正式业务没有只读预览时，不能伪造一次成功调用来满足 READY，也不能用未经授权的生产写入验证升级。

迁移和回退测试见 `tests/test_v2_migration_lifecycle_mysql.py`、`tests/test_plugin_migration_direct_mysql.py`；字段变化、局部决策变化的冻结宿主演练见 `tests/test_v2_maintenance_mysql.py`。这些测试使用隔离 MySQL、真实插件 ZIP/子进程和隔离外部接口，不连接生产业务库。

只有线上实例迁移、入口归属与业务验证闭合后，才可移除 V1 运行器、启动安装逻辑及签名发行依赖。历史执行事实和已执行 SQL 迁移不能当作旧源码一起删除。当前过渡发布仍使用[标准 ECS 发布流程](../agent/deploy/publish_to_ecs.md)。

插件自身入口按精确实例、包和已提交代次调用；安装其他版本或重复实例不能阻断该入口。目录中的跨插件依赖只计算已启用、已配置且提交稳定的实例，待配置和停用实例不占可调用路由。同一服务存在多个可调用实例时，裸服务名依赖仍明确拒绝，不按安装顺序或版本高低选择。真实 MySQL 安装新版 ZIP 后继续执行原统计实例的回归见 `tests/test_arrival_v2_configuration_mysql.py`。

迁移核验不把 TESTING 开始前已结束的原实例未知写当成本轮执行；历史记录及结果原样保留。任何仍活跃的调用、目标实例的未知写，以及本轮验证期间原实例产生的未知写仍阻止切换和撤回。统计与到货清单 Connector 共用 `list_connectors_v2.encode_arrive_page_result`，将现有读取适配器的固定列数组无损映射为字段对象；缺列、多列仍报错，不新增平台字段或业务默认值。
