# 任务领取与审批时间

此修复属于核心更新，涉及共享仓储、部署迁移和 Console 状态投影。数据库和服务器的时区配置保持原样。

## 时间职责

| 数据 | 时间口径与维护位置 |
|---|---|
| Run 默认可领取时间、恢复后唤醒、审批后唤醒 | `shared/orchestration_repository.py` 使用 `UTC_TIMESTAMP(6)` |
| Run 领取、Worker 租约、明确的未来重试 | 既有应用 UTC；不得将未来重试改为立即执行 |
| Approval 有效期 | `approval_service.py` 生成 UTC 期限；共享仓储按 UTC 判断过期、决定及消费 |
| 普通 Outbox 排队、租约与重试 | 沿用内部一致的数据库时钟，不与 Run 的应用 UTC 混用 |
| Command 提交时刻 | `requested_at` 是应用 UTC；无锁读取投影为 Run 的 `submitted_at` |
| 数据库创建/更新时间和旧混合字段 | 保留原始值；没有时区的值不能直接加 `Z` 声称是 UTC |

可领取时间表示最早执行时刻，用于真实的间隔重试和资源等待。手工新任务默认立即满足领取条件，仍需遵守实际并发、账号和资源互斥。

## 旧排队记录

迁移 `043` 固定捕获同一数据库语句的本地/UTC时刻、偏移和候选身份集合。只有能够证明仍是初始版本、从未领取、没有执行步骤/代际租约/写入回执、没有取消或重试意图、默认领取时刻等于创建时刻且因正时差被延后的首轮 RECEIVED 才进入候选。

更新时再次检查全部条件，仅纠正候选的领取时刻并增加版本；数据库自动更新时间随此次修改变化。取消记录、已开始记录、历史 UNKNOWN、已有重试和明确的未来延迟保持不动。快照在空集合时也保存；重跑、会话时区变化或后来新增任务不得扩大集合。迁移不创建新 Command，不把业务标记成功，不恢复已停止的历史 Run。

不修改 `041`/`042` 的内容或已保存历史边界，不对所有历史时间统一加减时差，不调整生产时区。`043` 不属于恢复 `018` 时删除的项目结构，不加入其重放清单。

## 页面

通用未领取状态只显示“任务已受理，等待开始执行”；只有实际资源等待才显示账号、数据位置或浏览器名额的具体原因。状态接口失败明确提示暂不可用，保留已受理任务身份并等待恢复；输出抽屉收起后仍刷新任务状态，终态结束轮询。

排队阶段优先使用已持久化 Command 提交时间。执行和结束阶段使用明确的 UTC 步骤/Run 时刻；旧数据库元数据及来源混合的时间以原始无偏移值输出，不猜时区。

## 验证与回退

隔离 MySQL 必须明确指向合成测试实例，设置 `PYTHON_DOTENV_DISABLED=1` 和 `RUN_MYSQL_INTEGRATION=1`。测试自身分别以 `+08:00` 和 `+00:00` 会话运行，不能靠把测试连接统一改 UTC 通过。

```sh
PYTHONPATH=agent:. python -m pytest -q \
  tests/test_orchestration_utc_mysql.py \
  tests/test_pending_run_timebase_migration_mysql.py \
  tests/test_control_plane_timestamp_projection.py \
  tests/test_control_plane_service.py
```

页面轮询用例位于 `console/tests/test_automation_run_controls.py`，执行实际模板 JavaScript，覆盖失败后恢复、收起后更新和终态停止。

按 [标准 ECS 发布流程](../agent/deploy/publish_to_ecs.md) 进行 shared 更新。先备份，再在隔离生产副本验证迁移候选、幂等及未涉及数据保持，最后由标准发布器执行生产迁移和激活。回退保留迁移历史、快照和发布后的业务数据；旧迁移器不认识新增版本，不能删除历史记录后强行重发旧提交。已领取的任务不能回拨为初始状态；需回退时准备兼容修复提交并按原发布门禁验证。
