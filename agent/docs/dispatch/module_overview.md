# 车辆调度模块概述

## 模块定位

车辆调度是 `物流 Agent` 的运力管理与调度执行层。它消费 OCR 识别和价格获取模块的结果，将运单数据与车辆资源进行匹配和分配，同时为财务对账和 AI 客服提供调度记录。

- 从 `OCR识别` 读取结构化运单字段（发货/收货地、货物信息）
- 从 `价格获取` 读取线路价格基线，辅助成本评估
- 向 `财务对账` 输出调度记录，用于成本核算
- 向 `AI客服` 输出车辆状态和轨迹，支撑客户查询

## 当前功能

- 车辆资源列表：车牌、车型、司机、状态实时展示
- 调度任务看板：今日调度记录、状态跟踪
- 距离查看面板：发货地/收货地 → 搜索推荐路线并突出展示距离，地图默认优先使用浏览器当前位置作为视图中心
- 运力统计概览：在途/待派/装货/维修车辆数、装载率
- 运费估算器：右侧边栏快速估价

## 工作区入口

- 调度工作区：`/dispatch`
- 模块详情页：`/modules/dispatch`

## 代码位置

- 页面模板：`console/templates/dispatch.html`
- 路由与数据：`console/app.py` → `_render_dispatch()`
- 样式：`console/static/style.css`（dispatch 相关 CSS 类）
- 地图接入：高德地图 JS API 2.0 官方 `AMapLoader`，环境变量使用 `AMAP_API_KEY`，如 Key 需要安全密钥则补充 `AMAP_API_secret`（兼容旧变量名 `AMAP_SECURITY_CODE`）；页面模板直接读取 `_render_dispatch()` 注入的 `dispatch_config.amap_js_key`
- 运行目录：`console/`
- 文档目录：`docs/dispatch/`

## 预期输入输出

- 输入
  车辆信息、运单数据、线路规则、司机排班
- 输出
  调度任务单、车辆轨迹、运力报表、异常预警

## 当前状态

- 工作区页面已接入统一后台壳层和共享动效，整体仍保留深色地图工作台风格
- 地图加载方式已切换为高德官方 JS API 2.0 Loader 写法，页面会优先请求浏览器当前位置作为地图中心，失败时回退到默认城市；不会自动回填“发货地”输入框
- 调度页地图初始化字段已与后端配置对齐，前端不再内置兜底 Key，避免因读取错误字段导致底图空白
- 路线搜索当前通过高德 `AutoComplete + PlaceSearch + Geocoder + Driving` 实时规划驾车路线，会优先按输入中的城市/区县上下文做 POI 消歧，再回退地址解析；地图与左侧结果卡会同步展示真实距离和时长
- 平台价格卡当前仍为本地估算值，但估算基线已改为实时路线距离，不再使用固定 mock 数字；货拉拉/运满满状态文案会明确标注“基于实时路线估算”
- 浏览器定位成功时，页面会把当前位置反查出的城市/区县作为兜底上下文，辅助短地名、园区名、公司名搜索；对于过短或过于模糊的输入，当前仍建议补充到城市/区县或更完整地址
- 发货地/目的地输入框现在会在输入阶段展示相似地址下拉候选；如果 `Geocoder` 只能给出低置信度行政点或与关键词不符的地点，前端会拦截自动落点，改为要求用户从候选中确认
- 路线结果区当前只保留推荐方案，主信息显示距离，次级信息显示时长；不再提供“开车去”跳转按钮
- 当前使用演示数据（6 辆车、4 条调度记录），后续对接真实数据源
- 调度相关可见功能当前集中在 `console/`
