
## 每日应签共享台账

- `arrive-list` 仅保存预计到货快照和应到资料，不证明实际到货，不启动应签计时。
- “统计到货数据”以 Asia/Shanghai 业务日期保存完整成功快照；同日只激活最后一个完整成功版本，任何下游输出失败都不得覆盖上一成功版本。
- 候选集合由当前 R13、历史进入 R13 且 TMS 未确认签收、实际到货件数大于零且目的站为“邵阳大祥S站”以及后来出现在该 R13 账号中的改单单号组成。零到货历史归档行和融辉子单号不构成应签候选。
- R13 提供 `R13应签收时间` 与参考签收状态；采集必须按原页“规划应签收时间”查询，未显式指定起止时间时至少覆盖前 2 天至后 3 天。原页不提供包装类型，该字段从实际到货或 TMS 运单详情取得。R13 单号消失、显示已签或完整空结果均不能关闭待签记录。
- 无实到时系统时间为空；正常到齐为业务日次日 23:59:59；部分到货无有效少货/分批事件也按首次部分到货次日计算。
- 少货/分批全部外部步骤成功且 TMS 登记时间严格早于 17:00:00 时，未齐期间系统时间为空；补齐当天恢复为当日 23:59:59。
- 人工问题件仅接受精确类型“客户要求延迟派送”“联系不上收件人”，且 TMS 登记时间严格早于 17:00:00；其应签到登记次日 23:59:59，多个事件取不早于现值的最晚日期。
- 批量关闭证据为 TMS“签收管理 → 签收查询”中 `BILL_CODE` 精确等于主单、且具有真实 `SIGN_DATE` 与 `SIGN_SITE` 的签收记录；对 R13 冲突及已离开当前 R13 的历史候选，可用快件跟踪页中主单扫描类型精确为“签收”的轨迹关闭。子单签收、R13 签收字段、空状态或其他扫描类型均不能关闭主单；未签精确核验按 1/3/7 天持久化退避。
- 普通飞书表固定九列：运单编号、R13应签收时间、问题件后应签时间、货物品名、包装类型、货物件数、收件人地址、送货方式、到货件数。普通表和多维表始终保留当前 R13 未签清单；已离开当前 R13 的历史候选只有在有效应签时间不晚于当前业务日时继续发布，历史口径 C 有值时以 C 为准，否则以 B 为准。表头不一致必须停止，B/C 两套时间互不覆盖；早于当前派件或首次到货生命周期的同号签收事件不得关闭当前运单。
- R13/问题件数据不完整时不发布；签收核验失败时只允许保守新增，禁止删除，并明确标记降级。所有运行保留来源行数、去重数、状态/质量数量和快照指纹。
