# 三平台报价

`quote_prices_v2` 1.0.8 是独立 Service V2 插件。融辉、韵达、百世的地址解析、产品选择与金额计算全部在 ZIP 内；Host 仅提供账号绑定、已保存登录态、受声明约束的只读 HTTP、最小业务上下文及执行记录。系统工具目录不提供报价工具，旧报价脚本已删除。

## 输入与结果

飞书发送 `报价 完整省市区及详细地址，重量，体积`，也支持直接发送 `完整地址，重量，体积`。重量单位公斤，体积单位立方米，填写时须为有限正数。也支持 `完整地址，重量`：省略体积时由插件默认按 0.1 立方米计算，并在结果注明；显式零、负数或无效体积仍报错。体积还支持 `长*宽*高*件数+...`，尺寸单位厘米。韵达要求地址包含完整省、市、区，省略省份可能无法解析。

每次查询分别返回融辉、韵达、百世三个结果块，自提与派送分别列出。1.0.3 同时显示本次匹配网点名称、地址、电话、派送范围和特殊区域等资料；平台未提供的必需展示项明确显示“无数据”，不能解释为“无特殊区域”。自提/派送匹配相同且资料一致时合并显示，不同时按方式分开；Console 选中报价的网点跟随该条报价。长说明在飞书分段发送，不截断。某平台或某种送货方式无有效报价时显示本次原因，其他成功结果仍保留；不得用上次金额、其他账号或默认费率填充。Console 手工录单调用同一项目，只比较用户所选送货方式，填写的重量和体积保留原输入精度；体积留空时同样交给插件按 0.1 立方米计算，不改写运单保存值。查询只测算价格，不保存或上传运单。

| 平台 | 本次计算口径 |
| --- | --- |
| 融辉 | 沿用原页详细地址匹配、线路和中心选择，查询可用产品与计费重量、最低保价；按当前费用明细汇总费用并减折扣，分别计算自提和派送。 |
| 韵达 | 从当前录单页读取账号上下文、表单及阈值；正式报价选中一口价，符合原页重量/体积条件时同时选韵重货，不符合时仅一口价；1.0.8 起另按取消一口价算出非一口价价格作为资料展示。按实际选项查询计费重量、保价区间和费用，再按原页规则选择费用合计并加当前消息费、截取两位。 |
| 百世 | 从当前账号读取发站，选择平台唯一默认且有效产品；分别解析派送、站点自提地址与服务权限，按现付、普通保价及平台当次最低保价测算，合计响应中实际有金额的费用项。 |

1.0.4 的韵达自提、派送分别注明本次“韵重货＋一口价”或“仅一口价（韵重货不适用）”。是否能选韵重货以当前页 `$BubbleRatio`、`$HeavyMinWeight` 为准：比率不为零，且重量严格大于 `体积 × 1000000 / 比率` 和最低重量；等于阈值时不选。计重和报价请求使用相同选项并取消大票货；若平台计重结果要求大票货、使一口价无法使用，则明确失败，不改报其他产品。

1.0.5 修正融辉二级网点判断：按 2026-11-08 读取的原页“运单录入”脚本，`ENABLE_ACCOUNT_PURPOSE`、`BL_PURPOSE_SITE` 以 JavaScript 宽松相等比较——`1/0` 改用上级网点，`0/1` 提示“网点暂停派送”，`0/0` 提示“无此网点”，其他组合（含平台省略或返回 null 的字段）保留匹配网点自身编码；此前插件把字段缺失当作必要字段错误，导致部分地址无法报价。派送下属网点的 `BL_PURPOSE_SITE`/`BL_OPEN` 判断使用同一比较规则。

1.0.8（2026-11-17，用户决定）韵达同时报一口价和非一口价，一口价为主：自提、派送的正式报价仍是一口价，名称改为“韵达自提（一口价）”“韵达派送（一口价）”；同一送货方式再按原页取消“一口价”勾选（`CheckFixedCost=0`，韵重货仍按原页重量／体积条件选择，大票货取消）重新计重、查保价并计算费用，结果写在资料最前面“韵达自提（非一口价）：…元”，回复里紧跟一口价价格。非一口价只作资料、不作报价，Console 比价仍只用一口价。依据 2026-11-17 只读读取的原页 `indexNew.html` 脚本：一口价与韵重货勾选只清除大票货，计重请求同时提交三个开关；计重结果要求大票货时原页改走大票货，该分支未完整核实，非一口价此时显示“无报价（平台计重结果要求大票货…）”，不猜价格。一口价失败时仍显示非一口价价格。

1.0.7（2026-11-17，用户决定）调整百世目的站点异常（`siteExceptionInterceptionVoList` 的 `handleType`）：“关注”（FOCUS）和“慎发”（CAUTION）照常报价，并把“注意：百世目的站点异常为…，价格照常测算，发货前请在原站核实”放在资料第一行，回复里紧跟价格；“停发”（DISCONTINUATION）或平台返回的其他级别不报价并写明范围与说明。此前任何站点异常都不报价，一条覆盖海南全省、有效期到 2036 年的“关注”提醒让海南地址的百世价格全部显示不出来。

1.0.6 修正韵达目的网点判断：按 2026-11-15 读取的原页“运单录入（indexNew）”脚本，地址归集 `getAchieveSiteByAddress` 单个网点 `info=2` 时原页只弹窗显示 `servicemsg`（如海南海运禁发货品提示），仍回填网点并可继续计费，插件随之继续报价，并把该弹窗内容作为首行“自提/派送原页弹窗提示”显示，不再重复列为“服务限制”；`info` 为 3（未匹配网点）、4/5（付款方式/代收限制）、6（关停线路）等其他值仍不报价，失败原因直接显示平台 `servicemsg`。此前插件把 `info=2` 一律当作“目的网点存在服务限制”，导致原页可正常计价的海南等地址无法报价。

特殊区域、需要人工指定网点/线路、额外派送加价等未闭合场景明确失败，同时保留本次已查到的网点和限制资料。融辉补查本次匹配派件网点的资料，单独资料查询失败时保留已成功价格并明确资料缺失；韵达 `SpecialArea` 集合按原页作为带相似度的“特殊区域参考”展示，不当作地址已命中；百世按当前模式的区域匹配结果展示收费标准、适用服务、说明与有效期。百世结果会注明当次最低保价，上楼、进仓等附加服务须另行核实。当前输入只有地址、重量、体积，不代表已覆盖全部特殊货物与附加服务。

## 安装、账号和入口

先发布支持通用多账号只读 HTTP、`account.context` 与动态输入的核心，再通过真实超级管理员的“自动化 → 安装扩展”上传 ZIP、检查权限、安装。安装默认停用；进入设置绑定三个账号角色：

| 角色 | 账号系统 |
| --- | --- |
| `ronghui_quote` | 融辉报价账号 |
| `yunda_quote` | 韵达账号 |
| `best_quote` | 百世账号 |

保存 Console `quote` 与飞书 `command` 入口后启用实例，回读版本、账号、committed generation 与生效入口，再执行一次真实查询验收。飞书精确路由为“三平台报价”，需沿用当前有效飞书身份与后台权限绑定。本包不声明定时或 Harness 入口；不得另建定时来处理每次询价。后续维护使用同一实例的升级入口。

账号登录失效时结束本次请求，在账号管理完成登录后重新发起查询。开发浏览器登录与 ECS 保存会话分别验证，不复制浏览器凭据到插件。源码提交、核心发布、ZIP 安装和真实业务验收各自记录，不能互相替代。

## 源码与验证

业务实现位于 `agent/service_v2_plugins/quote_prices_v2/payload/`，25 项只读请求在该目录 `manifest.json` 的 `http_requests` 中声明；网点/服务字段映射与中文 `details` 均在 ZIP 内，Host 只通用显示并在报价失败时保留；新增融辉声明 `ronghui_site_info` 调用 `FIND_SITE_DISP_INFO`，按原页派件网点标识读取资料并核对响应站点，韵达/百世复用当次地址匹配响应。账号业务上下文只返回融辉当前操作人和站点的四个必要字段，不返回认证材料。飞书与 Console 将本次输入传入真实 Direct Invocation；同一请求 UUID 重放必须匹配原调用的完整输入。1.0.2 的两个入口仅要求地址、重量；Host 省略未填体积，默认规则只在 ZIP 内维护，结果 `request.volume_defaulted=true` 记录本次默认值使用情况。

2026-10-11/12 已通过真实原页接口与未保存录单表单对照：融辉六个产品/方式组合、韵达两种方式、百世两种方式金额均一致。1.0.1 按真实原始 JSON 支持网点序号以整数值小数表示，仍校验整数、范围及网点名称；避免浏览器转换掩盖接口数值类型差异。2026-10-12 已逐平台核对原页网点字段、特殊区域语义与联系方式，新展示使用当次返回值。2026-10-12 已核对韵达原页两项选择及大体积无法选择韵重货时的一口价计算请求；计重、报价参数保持一致。真实地址和经营报价不入仓库。纯包测试使用虚构数据；`tests/test_quote_prices_v2_packaged.py` 使用真实 Linux 隔离进程、SDK 与 Broker，外部平台响应由模拟传输提供，覆盖 Console/飞书两个入口的组合选项、大体积仅一口价及平台当次计费重量传递，不能代替线上实例验收。

## 截图报价（2026-11-16）

飞书或微信发来截图（聊天记录、便签、单据）时，由当前激活的模型（2026-11-16 生产为 `deepseek-v4-flash`，可看图）经共用 AI 任务网关的 `quote.read_screenshot` 任务读出收货地址、截图里写明的重量和体积以及相关原文（`shared/screenshot_quote.py`）；代码核对地址和数字出自模型读到的原文，不合格即重试一次后失败。回复先写“识别到的收货地址：…”，再把与手工输入相同的“报价 地址，重量[，体积]”交给现有报价路由，权限、插件调用和结果回复不变；体积未写仍由插件按 0.1 立方米计算。没有重量时询问，同一人 15 分钟内的回复按两步理解：只是重量（可带一个体积，如“300公斤6个方”“2方，300”）由代码直接认，不调用模型；其他说法交给 AI 任务 `quote.read_follow_up`（`shared/screenshot_quote.py`），模型判断这句话是补重量（可同时改地址、给体积）、只改地址、取消还是与报价无关，并照抄原话里的重量数字和单位（公斤、千克、kg、斤、吨，由代码换算成公斤）、体积和新地址；代码核对数字和地址都出自这句原话（“1.5吨”不能读成 15，不能只取“300”里的“30”），不合格重试一次后放弃。补重量拼成标准“报价 地址，重量[，体积]”并先回复“识别到的收货地址…重量…体积…正在报价”再交给报价路由；只改地址则换成新地址重新问重量；取消回复“已取消”；无关或模型没给出合格结果时按普通消息处理，地址继续等待。确认、取消、固定命令、单号查询和完整“报价 …”不会交给模型（单独的“取消”同时清掉等待的地址），只有报价路由认不全的半句（如“地址改成…，一共1.5吨”）才交给模型。2026-11-16 起如此（此前只认固定写法，“300公斤6个方”被交给对话模型，模型不知道已识别的地址又反问地址）。需要有效身份且有“执行插件”权限，否则不调用模型。实现：`agent/agent/screenshot_quote.py`（识别与等待重量）、`agent/feishu/screenshot_quote.py`（飞书下载图片、微信交来的图片、身份检查、补充重量），微信图片按官方插件 2.4.10 的 `media-download.ts`/`pic-decrypt.ts` 下载并 AES-128-ECB 解密（`agent/agent/wechat_bot/ilink.py` 的 `download_image`）。飞书下载消息图片需要机器人有 `im:resource` 权限。
