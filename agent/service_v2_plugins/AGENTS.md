# 当前 V2 插件源码规则

当前业务动作只维护在本目录对应插件的 `payload/`；每日应签规则、采集和渲染在 `sync_daily_should_sign_v2/payload/business/`。Host 不维护应签类型清单或覆盖插件提交的判断。公共字段协议在根目录 `shared/ronghui_*_fields.py`，修改公共协议需要核心更新。

打包不得读取 `agent/legacy/` 或已退役的 `agent/first_party_automation_plugins/`。迁移历史、旧摘要和 SQL 保留用于离线回归，不能作为线上回退入口。维护与发布顺序见本目录 `README.md`；各插件现行版本以其 `manifest.json` 为准，线上版本以后台实例记录为准。

## 问题件判断的单一规则

- 分批显式提交问题件登记的 `before_cutoff/postpones_sign`，复用每日应签包内 `problem_event_flags`；共享打包器把同一规则及值解析模块放入各自独立 ZIP，不复制业务公式。
- 分批登记 Connector 严格要求显式分类字段，缺字段明确失败，不能用默认布尔值补齐。旧 Action V1 打包仅保持离线回归闭合，不恢复线上入口。
- M02/M03 维护演练分别使用财务、自提 V2 基线/候选/回退 ZIP，在冻结宿主上验证实际字段/判断变化；准备结果不作为正式冻结证据。

## 每日应签

- 只调用 R13 来源：先读取 R13 截至今天的全部未签收单（无起始日期，含超过30天旧单），再按本次单号批量读取数据库中的累计到货快照；不调用 TMS 问题件、签收、轨迹和详情，不加载清单外历史明细，也不重算清单外历史候选。必填账号只有 R13，TMS 账号角色仅作为可选历史配置保留。
- 到货件数按运单号取截至当前业务日该单最近一次成功有效的“统计”累计值，不跨日求和；当天统计未出现的单号沿用该单最近快照，并记录来源业务日期、运行编号及是否使用前日快照。最新快照为空不得取更早数字；从未有统计记录时普通表显示“无数据”、多维表数值列留空；真实0保持0。
- 报表、内部到齐判断和应签日期统一由 `calculate_arrival_state` 计算：连续两天累计2件仍是2件，不提前判齐；最新纠正为不足、0或空值会撤销旧到齐判断，0或空值不生成应签日期；未来业务日快照不参与。
- 普通表合并表头与数据读取，内容和尾部均一致时跳过写入、清尾及重复回读，变化时写入、清尾并完整回读；动态黄色条件格式由插件 `daily_sign_format.py` 维护，Host 只提供精确绑定表的格式读写。多维表只比较当前十二个托管字段，忽略旧列并统一飞书空单元格语义，未变化的记录不重写；未发生写入时复用本次完整新鲜读取完成核验，实际写入后重新回读。
- 详细协议及原页证据见仓库根 `docs/identity_and_unified_chat.md`。

## 扫描

- 默认每批 200 单，与 Host 提交接口上限一致；不同主单的子单可以同批录入。每批由 Host 打开一次浏览器，按下一站分组上传，再以融辉扫描账本权威回读核验，不一致记为未知写，不报告成功。
- 正式执行前重新读取来源并核对预览绑定；预览 15 分钟内有效，只能被同一次确认消费。

## R7车线每日打卡

- `r7_vehicle_checkin_v2` 只处理北京时间今天及前两天、运输状态为车辆到达（55）的任务；业务筛选和分页编排留在包内。
- 使用实例选择的 R7 账号及 Host `r7_vehicle_tasks@1` 接口；新鲜详情校验后逐条到达待卸，按服务器时间独立回读核验，不覆盖已有打卡，不自动通过额外确认，不自动重试未知写。
- 定时默认关闭，使用宿主简单设置选择账号和项目已有定时；旧 R7 到达/发车入口继续停用。构建、原站证据及安装前提见 `../docs/r7_vehicle_checkin.md`。
